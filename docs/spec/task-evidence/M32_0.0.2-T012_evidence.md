## Initial Runtime Finding

The first real J2ME tick smoke reached pinned WIE/RustJava startup but WIE panicked internally:

```text
called `Result::unwrap()` on an `Err` value:
JavaException(ClassInstance(java/io/FileNotFoundException))
```

The panic originated inside pinned `wie_j2me` during startup.

This exposed an adapter-boundary requirement: upstream backend panics must not terminate or unwind
through the M32 desktop process.

## FIX1 — Panic Containment

`WieSession::tick()` now contains upstream unwinds.

Behavior:

```text
WIE tick -> Ok(())
         -> SessionState::Running

WIE tick -> Result::Err(...)
         -> SessionState::Faulted
         -> SessionErrorCode::BackendTickFailed

WIE tick -> panic
         -> panic contained
         -> SessionState::Faulted
         -> SessionErrorCode::BackendTickFailed
         -> fixed sanitized message
```

Sanitized message:

```text
pinned WIE backend panicked during tick
```

The panic payload is not propagated into the M32 error.

The Rust panic hook may print the original panic diagnostic before `catch_unwind` regains control;
the acceptance criterion is that the test and host process continue and M32 receives the stable
failure.
