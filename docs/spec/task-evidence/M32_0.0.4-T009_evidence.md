
## Duplicate Contract

A key-down for an already-held key returns:

```text
AlreadyHeld
```

and does not:

```text
emit another KeyDown
duplicate held state
reset the repeat origin
```

After releasing one held key, a previously rejected key can be accepted into the free slot.

## Deterministic Ordering

When multiple held keys become repeat-due at the same poll, repeat events are emitted in stable
held-key insertion order.

This keeps future deterministic replay behavior stable.
