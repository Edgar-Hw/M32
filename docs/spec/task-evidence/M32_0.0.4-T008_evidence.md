## Goal

Lock the backend-independent host-side guest repeat policy.

## Contract

```text
initial repeat delay = 350ms
repeat frequency     = 12Hz
```

The first repeat is due exactly at:

```text
press_time + 350ms
```

Subsequent repeat counts are derived from the original press/repeat origin instead of chaining
`now + interval` deadlines.

Integer-millisecond boundaries are therefore deterministic:

```text
350
434
517
600
684
767
850
934
...
```

A delayed poll catches up the repeats that are already due without moving the original schedule
origin.

## Release Semantics

Releasing a held key:

```text
emits one KeyUp
removes the key from held state
stops all future repeats
```

A later duplicate release emits nothing.
