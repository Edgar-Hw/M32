Adapter compile exposed two pinned-WIE compatibility requirements.

### FIX1-A — Public RecordId path

Initial adapter used:

```text
wie_backend::database::RecordId
```

but the pinned WIE `database` module is private.

WIE publicly re-exports the type alias from crate root, so FIX1 changed all adapter signatures to:

```text
wie_backend::RecordId
```

The locked underlying type remains:

```text
u32
```

Final source verification showed all expected `wie_backend::RecordId` signatures and no remaining
`wie_backend::database::RecordId` path.

### FIX1-B — Effective async Send/Sync requirement

Initial M32 database host contract:

```text
GuestDatabaseHost: Send
```

failed because WIE's default `async_trait` expansion creates `Send` futures for `&self` methods such
as `next_id`, `get`, and `get_record_ids`.

The adapter therefore requires the held host trait object to be Sync.

FIX1 changed the M32 contract to:

```text
GuestDatabaseHost: Send + Sync
```

No record semantics or persistence behavior changed.
